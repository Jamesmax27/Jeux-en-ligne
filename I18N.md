# Internationalisation — 5 langues

Site et jeux en **français** (langue source), **anglais**, **espagnol** (neutre), **portugais** (Brésil) et **allemand**.
Ce document décrit l'architecture choisie, les décisions prises et l'état de chaque jeu et de chaque jaquette.

## 1. Analyse du dépôt (point de départ)

- Site statique sans framework (`public/`), publié par Cloudflare Pages ; catalogue `catalog.json` généré par `scripts/build-catalog.mjs` à partir de `games/*/game.json`.
- Les jeux tournent dans un **cadre isolé** (`sandbox="allow-scripts"` sans `allow-same-origin`, affiché via `srcdoc`) : ils n'ont **pas accès** au `localStorage` du site, ni au réseau (CSP).
- Votes : `public/votes.js` → `functions/api/vote.js` (D1). Le tri et les votes ne dépendent d'aucun texte : ils ne changent pas.
- **Jaquettes** : ce sont des **captures d'écran de l'écran d'accueil du jeu** (Playwright, 600 × 800, JPEG qualité 80 : `validate-games.mjs --covers`, lancé par la boucle de nuit). Quelques jaquettes plus anciennes (`.webp`) sont des captures de partie faites à la main, à d'autres tailles. Une seule a une source : `poings-de-pierre/cover.svg` (SVG écrit à la main). Elles contenaient presque toutes le titre et la règle en français.
- Workflows : `validate.yml` (pull requests : `validate-games.mjs --browser`), `boucle-de-nuit.yml` (création automatique des jeux), `idee-jeu.yml`, `corriger-jeu.yml`.

## 2. Architecture

### Module commun `public/i18n/i18n.js` (servi à l'adresse `/i18n/i18n.js`)

Un seul fichier, JavaScript pur, sans dépendance, utilisé **par le site et recopié dans chaque jeu** (`window.JEL_I18N`, plus le raccourci global `t()` s'il est libre).

- Langues `["fr","en","es","pt","de"]`, secours `en`.
- Détection : `?lang=xx` (enregistré comme choix) → choix enregistré (`localStorage["lang"]`, ou `window.JEL_LANG` transmis par le lanceur au jeu) → `navigator.languages` (préfixe : `pt-BR` → `pt`) → `en`.
- `getLang()`, `setLang(code)`, `t(cle, variables)` (`{variable}`, pluriels `{ "one": …, "other": … }` via `Intl.PluralRules`, variable `n`), `has()`, `nombre()` et `date()` (`Intl`), `appliquer()` (attributs `data-i18n`, `data-i18n-html`, `data-i18n-placeholder`, `data-i18n-title`, `data-i18n-aria`), `creerSelecteur()`.
- Clé absente : texte français, sinon la clé brute, avec un avertissement `[i18n]` dans la console (une fois par clé).
- Sélecteur de langue : bouton avec le code (FR, EN, ES, PT, DE), liste avec code + nom dans sa langue (Français, English, Español, Português, Deutsch), sans drapeaux ; doigt et clavier (Entrée, flèches, Échap).

### Site

- Textes : `public/i18n/site/{fr,en,es,pt,de}.json` (interface, genres `genre.*`, univers `univers.*`, tranches d'âge `age.*`, tags `tag.*`, messages de vote, erreurs, pied de page). Les identifiants internes (genres, tags, `id` des jeux) ne changent pas.
- `public/langue.js` : chargement des textes, sélecteur dans l'en-tête, SEO, noms affichés (genre, tag, titre et description traduits du jeu).
- Catalogue (`app.js`) et lanceur (`play.js`) : tout texte passe par `t()`. Changer de langue met la page à jour sans la recharger ; le tri, les votes et les filtres ne changent pas (le départage final du tri reste le titre français, pour un ordre identique dans toutes les langues).
- **Titre sur la jaquette** : le titre traduit est affiché par le site en bandeau en bas de la jaquette (dégradé bleu nuit, 3 lignes au plus, coupure des mots longs) ; les jaquettes ne contiennent plus de texte.
- SEO : `<html lang>`, `<title>` et meta description suivent la langue ; liens `<link rel="alternate" hreflang>` pour les 5 langues + `x-default` (adresse `?lang=xx`), ajoutés par `langue.js` ; `sitemap.xml` (accueil et chaque jeu, une entrée par langue avec ses variantes) et `robots.txt` générés par `build-catalog.mjs`.
- Hors ligne : `langue.js`, `i18n/i18n.js` et les 5 fichiers de langue font partie de la coquille du service worker (`VERSION` passée à `v4`).

### Jeux

- Chaque jeu reste **un seul fichier autonome**. Dans son `<head>`, avant tout autre script :
  1. `<script type="application/json" id="jel-i18n-textes" data-coin="…">{ "fr": {…}, "en": {…}, "es": {…}, "pt": {…}, "de": {…} }</script>` : tous ses textes ;
  2. `<script id="jel-i18n">…</script>` : copie exacte de `public/i18n/i18n.js` (mise à jour par `node scripts/i18n-jeu.mjs`).
- Le code du jeu utilise `t('cle', { variables })` (canvas compris) ; les textes fixes du HTML ont `data-i18n="cle"`.
- Petit bouton de langue discret dans le coin choisi (`data-coin` : `haut-gauche`, `haut-droite`, `bas-gauche`, `bas-droite`).
- **Choix partagé avec le site** : le cadre isolé ne peut pas lire le `localStorage` du site ; le lanceur transmet donc la langue au jeu (`window.JEL_LANG`, ajouté au début du `srcdoc`). Quand on change de langue dans le jeu, celui-ci envoie un message `jel-langue` au lanceur, qui enregistre le choix (même `localStorage` que le catalogue) et **relance le jeu** dans la nouvelle langue. Jeu ouvert seul (`/games/<id>/`) : même domaine que le site, donc même `localStorage` ; le jeu se recharge avec `?lang=xx`.
- Fiche `game.json` : `title` et `description` restent en français ; leurs traductions sont dans `"i18n": { "en": { "title", "description" }, "es": …, "pt": …, "de": … }`. Champs facultatifs : `"non_traduisible": true` (jeu dont le contenu dépend du français : seule l'interface est traduite ; le catalogue indique « en français ») et `"langues": ["fr"]` (le catalogue ne le propose que dans ces langues).

### Jaquettes sans texte

- `scripts/jaquette-sans-texte.mjs <id>` : même méthode que les jaquettes existantes (capture du jeu dans Chromium), mais en masquant **tous** les textes (HTML, SVG, canvas `fillText`/`strokeText`), en gardant dessins et emoji. Même nom de fichier, mêmes dimensions que la jaquette existante, même qualité (JPEG/WebP 80).
- `validate-games.mjs --covers` (jaquette automatique des nouveaux jeux, boucle de nuit) utilise la même fonction : les futures jaquettes sont aussi sans texte.

### Vérification `scripts/check-i18n.js`

`node scripts/check-i18n.js [ids…] [--statique] [--rapport]` — sort en erreur (code 1) si : JSON invalide, clés différentes de `fr`, valeur vide, `{variables}` différentes, pluriel sans `other`, genre/univers/âge sans nom, titre ou description manquant dans une langue (`game.json`), bloc de textes ou module commun absent ou pas à jour, clé utilisée par un jeu absente de `fr` ; avec un navigateur (Playwright), erreur JavaScript, clé manquante ou `<html lang>` faux au chargement de chaque jeu, du catalogue et du lanceur dans les 5 langues. Rapport non bloquant : textes en dur suspects (`i18n-rapport.txt`), tags non traduits, CSS de bouton à largeur fixe ou `nowrap`, textes qui débordent (navigateur). Branché comme étape bloquante dans `.github/workflows/validate.yml`.

## 3. Décisions prises (options les plus simples)

| Sujet | Décision |
| --- | --- |
| Emplacement de `/i18n/` | Dans `public/i18n/` (dossier publié) : servi à `/i18n/i18n.js` et `/i18n/site/*.json`. |
| Un seul module pour site et jeux | `i18n.js` est un script classique (pas un module ES) : il marche en `<script src>` sur le site et recopié en ligne dans les jeux. |
| Langue d'un jeu dans le site | Transmise par le lanceur (`window.JEL_LANG`) car le cadre isolé n'a pas de stockage ; changer de langue dans un jeu **relance** le jeu (plus simple et fiable que retraduire chaque texte en direct, canvas compris). |
| `?lang=xx` | Enregistré comme choix (les liens hreflang mènent donc à une langue qui reste). |
| Clé absente | Repli sur le français (pas sur l'anglais) puis clé brute, comme demandé ; « en » ne sert qu'à la détection. |
| Titres/descriptions des jeux | Dans `game.json` (`i18n`), pas dans un fichier séparé : une pull request de jeu ne touche toujours que `games/<id>/`. |
| Tags | Traduits dans les fichiers du site (`tag.*`). Un tag nouveau sans traduction affiche le mot français (avertissement de `check-i18n.js`, non bloquant, car une pull request de jeu ne modifie pas les fichiers du site). |
| hreflang | Ajoutés par JavaScript avec l'adresse réelle (domaine pas encore choisi). `sitemap.xml` : variable `SITE_URL` du build Cloudflare, sinon `https://jeux-en-ligne.pages.dev/` (à régler avec le nom de domaine). |
| Format des jaquettes | Les noms de fichiers ne changent pas (`cover.jpg` reste `.jpg`, `cover.webp` reste `.webp`), pour ne rien casser. |
| Manifeste PWA (`manifest.webmanifest`) | Reste en français (un manifeste n'a qu'une langue). Son nom « Jeux-en-ligne » est une marque. |
| Nom du site « Jeux-en-ligne » | Marque : non traduit. |
| Formulaire « Nouvelle idée de jeu » (GitHub) | Reste en français : il sert au propriétaire, sur GitHub, hors du site. |
| Textes `console.*` et commentaires | Non traduits (destinés aux développeurs). |

## 4. Où insérer la traduction dans la boucle de nuit (à faire plus tard)

La boucle (`.github/workflows/boucle-de-nuit.yml`) n'a **pas** été modifiée. Les consignes de création (`CONSIGNES-JEU.md`, `CLAUDE.md`) demandent déjà aux agents un jeu traduit, et la jaquette automatique (`--covers`) est déjà sans texte. Pour rendre la traduction obligatoire dans la boucle :

1. Étape c (fabrication, job de l'agent créateur) : ajouter `Bash(node scripts/check-i18n.js:*)` aux `--allowedTools` et, dans le prompt, une étape « lance `node scripts/check-i18n.js <id>` jusqu'à « tout est bon » ».
2. Étape « Contrôle qualité final + jaquette » : ajouter `node scripts/check-i18n.js "<id>"` après `validate-games.mjs` (même `pipefail`).
3. Étape d (vérification) : ajouter `check-i18n.js` au robot, et un point « Traductions » à la grille de relecture (`CONSIGNES-JEU.md`, section 7).
